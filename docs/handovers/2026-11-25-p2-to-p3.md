## Open items from the P2b review (to do in P3)

1. **Unchecked creates (P3 D-entry).** devready has `required = false`, and `file-block#devready`
   takes any code span + colon with `default_op = "create"`. In a task without a manifest a
   Create gets no manifest check; in a task with one, an undeclared Create is only a warning.
   The corpus hits it only in rules-logging Task 5 (two files). Proposal: a write to a path that
   is not a manifest entry, or in a task without a manifest, is shown and confirmed, never
   automatic. This is exec policy, in every format; decide it with Rens when the P3 policy
   surface is designed.
2. **`before-after#series` ignores its leading word.** `^(?:\w+ )?[Ee]dit (?P<n>\d+)…`: a
   "README edit 2" directly after "`x.ps1`, edit 1" would continue the series and edit `x.ps1`.
   No real plan hits it, and the failure would be loud (`before` must occur once). Fix in P3's
   first spec touch-up: when the word is present it must equal the file-name stem of the
   continued path, or there is no continuation. Add a synthetic case.
3. **`manual-prose#run-from` is end-anchored** (`` `):$ ``): "… (run from `x`) (Bash tool):" would
   bypass it and be claimed by the `(Bash tool):` lead. Drop the end anchor in the same
   touch-up as item 2.
4. **Negated failure wording in exit tables.** The devready (and superpowers, before-after)
   expected-prose tables map `\b(?:fails?|build errors?)\b` to `failure` first, so "nothing
   fails" would become an expected failure that D12 skips. No current devready expectation
   maps to failure (checked at review), but put a negation row first (success or any) in the
   same touch-up, with a synthetic case.
5. **The Apply invariant is format-wide.** It sits in plan-grammar §5 (before-after); devready's
   `script` has an `-All` apply intent too. Move it to §1 when P5 enforces it.
6. **P4 candidate, already in the roadmap:** a script working directory from a run lead
   (`` (run from `$REPO`): ``). `Script` has no cwd, so such fences are Manual in devready.

## How plans are written and verified here

As in P1, P2a and P2b: read what the phase needs, ask the open questions, and stop. Then build
in a scratch clone outside the repository (`git clone -c core.autocrlf=false`), one commit per
task, with the gate at every commit. Generate the plan from the scratch history, run
`planrun check` on it, and replay it on a fresh clone with `core.autocrlf=true`. Copy it to
`docs/plans/` and stop for review. Scripts live in the session scratchpad and are gone with it;
rewrite them:

- `run_gates.py` checks out each commit in a worktree, runs fmt, clippy, `cargo test` and the
  task's targeted command, and stores the `test result:` lines with `finished in …s`.
- `gen_plan.py` writes the assay plan:
  - full contents from `git show`, an exact diff for a modified file over 300 lines;
  - a fence one backtick longer than any backtick run at 0–3 spaces of indentation in its body;
  - a commit step with the blob id of every staged file.
- `replay.py` writes the full-contents blocks (LF), runs the patch ceremony, gate and commit in
  one pwsh session per task, and checks `git status --porcelain` after each.

Gotchas, in addition to the P1 and P2a ones (final newlines, Git Bash heredocs that turn `\b`
into a backspace, `python -I` and local modules, copying only `tests/corpus/local/20*.md`):

- **Write Python edit scripts with the Write tool, never a Bash heredoc**, and never start a
  command that reads stdin (`cat > file` with nothing piped in hangs the shell).
- **The replay must find the end of the tasks by its heading** (`## P<N> green state`), not by the
  first `## ` line after the last task: a full-contents block of a Markdown file has `## `
  lines of its own.
- **Scan the scratch diff for real-plan text before generating** (D16): file names, label titles,
  repository variables and sentences from the local plans slip into test data, toml comments and
  doc examples. Replace them with generic text and fold the fix into the task it belongs to
  (`git commit --fixup` + `GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash <base>`), then
  re-run the gates: the commit ids change.
- **A view field added for a new feature** (`ExpectView.comments`) needs
  `skip_serializing_if = "Option::is_none"`, or every existing IR snapshot changes.
- **Rulings relayed from a review seat** are checked against the code and the plans before acting
  (CLAUDE.md, Working with Rens): where a premise is wrong, keep the position and state the
  evidence in the plan's stated decisions.
