## Open items (from the P3 review; required before P5 runs `commit` outside the tests)

1. **The write-ahead record** (D53): P5's journal implements `WriteAhead` and persists the
   `PreparedStep` before `commit` writes anything. A real run without it is not allowed.
2. **File mode.** `Workspace::write` creates its temp file with default permissions, so an
   Overwrite of a 100755 file drops the exec bit on Linux; a patch with `old mode`/`new mode` or
   `new file mode 100755` gives `PlannedWrite` bytes but no mode. Apply the post-image's mode
   (virtual index, or the target's permissions) to the temp file before the rename, under
   `core.filemode`; a D-entry. Windows with `core.filemode=false` is unaffected.
3. **The gap between prepare and commit.** P5 puts D50's prompt between them. Right before the
   write-ahead record, `commit` re-hashes each touched path (`hash-object --no-filters` without
   `-w`, or compares bytes); any difference, or a path that appeared or vanished, aborts with
   nothing written, and the step is prepared again.
4. **`via_git` Delete in a real preflight.** In `preflight()` on the real disk, a `via_git` target
   that is not tracked is a plan error (a manual `git rm` would fail). The dry run keeps stated
   decision 16 (no tracked check).
5. **`git gc` and pre-images** (D57): decide detection (the object is gone: the user decides,
   D14) or pinning (a ref under `refs/planrun/`).
6. **Dirt from planrun's own writes.** A task after one whose commit is Manual (devready, D33)
   sees planrun's uncommitted writes as dirt; the runner knows which paths it wrote and must tell
   them apart. Also: a commit script that stages everything (`git add -A`, `git add .`) on a tree
   with unrelated dirt.
7. **`.planrun-*.tmp` debris** after a crash between the temp write and the rename.
8. **D50's prompt** for unscoped file actions (the dry run reports them as "would ask").
9. **Repeated `Generated` notices** are one check (architecture §3); the dry run lists both.
10. **Report wording:** `files: N problem(s)` beside the trailer's `M error(s)`; align it when P5
    reworks the report.
11. From the P2→P3 handover: item 5, the Apply invariant moves from plan-grammar §5 to §1 when P5
    enforces it; item 6, a script working directory from a run lead (P4, below).

## How plans are written and verified here

As in P1–P3: read what the phase needs, ask the open questions, and stop. Then build in a scratch
clone outside the repository (`git clone -c core.autocrlf=false`, copy only
`tests/corpus/local/20*.md`), one commit per task, with the gate at every commit. Generate the
plan from the scratch history, run `planrun check` on it, and replay it on a fresh clone with
`core.autocrlf=true`. Copy it to `docs/plans/` and stop for review. Scripts live in the session
scratchpad and are gone with it; rewrite them:

- `gate.sh`: fmt, clippy, `cargo test`, the local-corpus test, and a diff of `planrun show` and
  `planrun check` on the six local plans against a baseline captured at the base commit.
- `run_gates.py`: checks out each commit in a worktree, runs fmt, clippy, `cargo test` and the
  task's targeted command, and stores the `test result:` lines with `finished in …s`.
- `gen_plan.py` (with the hand-written text in a separate module): full contents from
  `git show`, an exact diff for a modified file over 300 lines, a fence one backtick longer than
  any backtick run at 0–3 spaces of indentation, a commit step with every staged blob id. It
  refuses a body without a final newline.
- `replay.py`: writes the full-contents blocks (LF), saves each diff where its lead says, runs
  the ceremony, targeted command, gate and commit in one pwsh session per task, and checks the
  commit subject and `git status --porcelain`. Compare the replay's final tree id with the
  scratch tree id.

Gotchas, in addition to the P1–P2b ones (final newlines, heredocs and `\b`, `python -I`, Write
tool for Python edit scripts, the replay finding the end of the tasks by its heading, D16 scans,
`skip_serializing_if` for new view fields):

- **Files without a final newline in the base** (several docs, toml and corpus files) make a
  full-contents block impossible to carry exactly. The first task that touches one adds the
  newline; the generator refuses such a body, so this shows up before the plan exists.
- **The replay splits tasks at `### P<N>-T<n>:` headings outside fences only:** a corpus file in
  a full-contents block has task headings of its own.
- **Parse the replay's markers from stdout only:** git's CRLF warnings on stderr otherwise end up
  in the commit subject the replay compares.
- **The fixture on an `autocrlf=true` checkout is CRLF.** The helper copies it as LF; a scratch
  clone with `core.autocrlf=false` cannot show such a bug, the replay can. Keep the replay.
- **insta writes `assertion_line:` into new snapshots;** the existing ones have none. Strip it
  when accepting a `.snap.new`.
- **Trailing spaces in Rust string literals** (blank context lines in test patches) get lost on
  the way through editors; write them as `\x20`.
- **`sed -i` and inline Python with `\n` in Git Bash** mangle escapes; use the Edit tool or a
  Python file written with the Write tool.
- **After execution, compare the executed tree with the verified one** (`git ls-tree -r HEAD`
  against the scratch clone's), not only the gate: open item 0 passed every test.
