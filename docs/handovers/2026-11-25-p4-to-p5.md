## Open items

Each is required before P5's runner uses sessions or `--auto`; none is reachable in P4, which
executes no plan.

### From the P4 plan review

1. **A session can hang forever.** When the shell dies without a sentinel
   (`[Environment]::Exit`, `Stop-Process -Id $PID`, bash with its EXIT trap replaced) while a
   descendant (a build server, a background job) holds stdout or stderr, `Session::collect` waits
   for EOF indefinitely, and there is no default timeout (D65). Fix: `collect` notices that the
   shell itself exited (`try_wait` in time slices, or a waiter thread that sends an event), kills
   the tree so the pipes close, and reports `SessionEnded(None)`.
2. **A failed block write leaves the session out of step.** `ShellSession::run` increments
   `block` before writing and renaming the block file; when either fails the session stays
   alive, pwsh waits for `b<n>` forever and the next run writes `b<n+1>`. Any I/O error in `run`
   must end the session.
3. **`source` can be shadowed.** bash's block line calls `source`; a plan function of that name
   replaces it. Use `builtin source`, as the wrapper already does for `printf`.
4. **An orphaned pwsh session on Unix.** After a planrun crash, pwsh (no stdin) polls for block
   files forever; bash exits on stdin EOF, and on Windows the job object kills it. Decide one:
   `PR_SET_PDEATHSIG` in `kill.rs` on Linux, or the loop exits when its parent is gone.
5. **`-ExecutionPolicy Bypass`** also lifts the Mark-of-the-Web check for scripts a block calls.
   `RemoteSigned` (pwsh's Windows default) would still run the local block files and keep the
   terminal's behaviour for downloaded scripts. Low impact (such calls are Destructive). Decide
   it with a D-entry.
6. **sed is Read too often.** Without `-i` it is Read, but GNU sed's `w`, `W`, `e`, the `s///w`
   and `s///e` flags, and `-f` scripts write files or run commands. Before `--auto read` runs
   anything unasked: Read only when the script has none of these, otherwise Modify (`w`, `W`) or
   Destructive (`e`, `-f`).

## How plans are written and verified here

As in P1–P4: read what the phase needs, ask the open questions, and stop. Then build in a scratch
clone outside the repository (`git clone -c core.autocrlf=false`, copy only
`tests/corpus/local/20*.md`), one commit per task, with the gate at every commit. Generate the
plan from the scratch history, run `planrun check` on it, and replay it on a fresh clone with
`core.autocrlf=true`; the replay's final tree must equal the scratch tree. Copy the plan to
`docs/plans/` and stop for review. Scripts live in the session scratchpad and are gone with it;
rewrite them:

- `gate.sh`: fmt, clippy, `cargo test` with `PLANRUN_REQUIRE_SHELLS=1`, the local-corpus test,
  and a diff of `planrun show` and `planrun check` on the six local plans against a baseline
  captured at the base commit.
- `run_gates.py`: one git worktree next to the scratch clone (with the local plans copied in),
  checks out each commit, runs fmt, clippy, `cargo test`, the task's targeted command, the
  local-corpus test and the baseline diff, and stores the `test result:` lines in `gates.json`.
- `gen_plan.py` with the hand-written text in `plan_text.py`: full contents from `git show`, an
  exact diff (`git diff`) for a modified file over 300 lines, a fence one backtick longer than
  any backtick run at 0–3 spaces of indentation, the summary lines from `gates.json` with
  `finished in …s`, a commit step with every staged blob id. It refuses a body without a final
  newline.
- `replay.py`: writes the full-contents blocks (LF), saves each diff where its lead says, runs
  the ceremony, targeted command, gate and commit of a task in one pwsh process, and checks the
  commit subject, `git status --porcelain` and the final tree.

Gotchas, in addition to the P1–P3 ones (final newlines, heredocs and `\b`, `python -I`, the
replay splitting tasks at headings outside fences, stdout-only markers, CRLF fixture copies,
`assertion_line:` in new snapshots, `\x20` for trailing spaces in string literals, `sed -i` and
inline Python with `\n` in Git Bash):

- **Python edit scripts with `\n` in them must be written with the Write tool**, never as a
  heredoc in Git Bash: the heredoc turns `\\n` into a real newline inside Rust string literals
  (it broke two edits in P4).
- **The replay must forget a block's lead after its fence.** Otherwise the ceremony fence after
  a diff is taken for the diff and overwrites the saved patch (P4's first replay).
- **rustfmt puts each element of a string array or table row on its own line** once elements are
  long; keep table tests and constant tables compact with `#[rustfmt::skip]` (CLAUDE.md, test
  conventions), or the plan grows by hundreds of lines.
- **pwsh native commands inherit pwsh's stdin**: any session or test that feeds pwsh on stdin
  can hang a native command that reads it (`git hash-object --stdin`).
- **Process tests on Windows:** a grandchild's PID from Git Bash is in `/proc/<pid>/winpid`; check
  it with `tasklist`.
- **After execution, compare the executed tree with the verified one** (`git ls-tree -r HEAD`
  against the scratch clone's), not only the gate.
