## How plans are written and verified here

This is what made P1 land cleanly; repeat it for P2.

1. Read the real plans' structure outside fences first (an awk pass over the file that prints
   non-fence lines and fence openers is enough). Never copy their content into committed files.
2. Ask the open questions and stop. After the answers, build the phase in a **scratch clone**
   outside the repository (`git clone -c core.autocrlf=false`), one commit per task. Run the gate
   at every commit and take the "N passed" counts from those runs.
3. Generate the plan from the scratch history with a script:
   - full contents from `git show <commit>:<path>`;
   - an exact diff (`git diff <commit>~1 <commit> -- <path>`) only for changed files over 300
     lines and for `Cargo.lock`, so cargo resolves nothing again;
   - every fence one backtick longer than any fence line inside it, or the plan breaks its own
     `unclosed-fence` rule;
   - each commit step checks every staged file's blob id (`git rev-parse :<path>`) against the
     scratch commit. It cannot check a whole-tree id: the plan is committed first, and a plan
     cannot name a tree that contains itself.
4. Run `planrun check` on the generated plan: it must exit 0 with no Manual blocks you did not
   intend. Keep plan prose free of the manual markers (`by hand`, `manual step`, `Rens runs`)
   unless a Manual block is meant.
5. Replay the plan on a fresh clone with Rens' git settings (`autocrlf=true`): commit the plan,
   write each full-contents block, `git apply` each diff, run each commit block in `pwsh` with
   `$gate = 0`, then run the gate. Every commit must land with a clean `git status`.
6. Copy the plan to `docs/plans/` and stop for review. If the base moves meanwhile (Rens commits),
   rebase the scratch history, re-run the gates, and regenerate the plan.

Gotchas:

- In Git Bash heredocs that feed Python, `\\n` came through as a real newline. Write edit
  scripts with the Write tool instead.
- Integration test files need a `//!` crate doc: `missing_docs` is a warning, so clippy fails
  without it.
- `cargo test` output order: the bin's unit tests, its integration tests, then each lib's unit
  tests and integration tests (alphabetical), then the doc-tests. The plan's Expected blocks rely
  on this order.
