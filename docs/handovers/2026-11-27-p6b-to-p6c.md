## The surface P6c builds on (all in planrun-exec)

- **`ui::Ui`** (`status`, `output`, `ask`, `view`, `diff`, `shell`): the TUI implements it on the
  runner's worker thread, forwarding over channels; `ask`, `shell`, `view` and `diff` are
  blocking round trips to the render thread (D90). `Question { kind: QuestionKind, at, text,
  choices, typed }`: keys come from `choices`, typed input from `typed`; the dock matches
  `QuestionKind` exhaustively (16 variants; `name()` is the journal name).
- **`journal::Journal::observe(Observer)`** with `Seam::{Appended(&Record), Wrote(n)}`: the live
  view's source. `Observer` is `Box<dyn FnMut(Seam)>`, not `Send`: build it on the worker thread,
  capturing a `Sender`. planrun-cli's e2e seam (D82) uses another observer on the same journal.
- **`shell::OutLine { stream, text, newline }`** through `Ui::output`: the console.
- **`shell::end_now(code)`** for Ctrl-C after the dock's confirm (restore the terminal first);
  **`shell::InterruptsIgnored`** while the `[o]` shell runs (D73).
- **`preflight::dry_run`** → `DryRun { start, tasks: [TaskReport { manifest, actions:
  [ActionReport { step, action, outcome }] }] }` for Inspect; `DefaultClassifier::explain` and
  `Policy::decide` for its class and policy column.
- **`expect::align`**, and `QuestionKind::Mismatch { status, mismatches, output, aligned, commit,
  dead }` for the mismatch dock.
- **`runner::resume::analyse`** and **`runner::preview::preview`** → `Preview { live,
  plan_changed, index_lock, now, head: HeadVerdict, steps, again, resume_dirt }` for the resume
  preview; it reads only, takes no lock.
- **`lock::live(dir)`** (a try on `lock.live`, never on `lock`) and **`lock::holder(dir)`** (the
  pid in `lock.pid`, shown only) for "running in pid N" and "killed" (`journal::dir(git_dir)` is
  the directory).
- **`runner::Runner::{run, resume}`** with `RunConfig { plan_path, policy, from, to, session }`,
  as planrun-cli's `run.rs` uses them; take the lock with `lock::acquire` as `run.rs` does.

## How plans are written and verified here

As before: read what the phase needs, ask the open questions, and stop. Then build in a scratch
clone outside the repository (`git clone -c core.autocrlf=false`), one commit per task, with the
gate at every commit (plus `cargo clippy -p planrun-exec --all-targets --target
x86_64-unknown-linux-gnu -- -D warnings` when Unix code changes). Generate the plan from the
scratch history (full contents from `git show` for created files and modified ones up to 300
lines, exact diffs from `git diff` above that or without a final newline, blob ids from
`git rev-parse`), run `planrun check` on it, and replay it with planrun itself on a fresh clone
with `core.autocrlf=true`: an `e2e` release build of the base (`cargo build --release -p
planrun-cli --features e2e`, copied outside `target/`), `--auto read,build,modify`, and answers
from a file of `yes`, `y`, empty line repeated (a typed question takes `yes`, a confirmation `y`,
a notice enter; anything else asks again). The replay's final tree must equal the scratch tree.
Copy the plan to `docs/plans/` and stop for review; review rulings go into the plan's "Review
rulings" section, and a changed plan is regenerated and replayed again.

The scripts live in the session scratchpad and are gone with it; rewrite them: `gate.sh` (the
gate), `run_gates.py` (a worktree, each commit's gate and targeted commands, summary lines into
`gates.json`), `gen_plan.py` with the hand-written text in `plan_text.py` (the P6b plan shows the
shape: Goal, task list, Base, Shell and environment, Before, How verified, Review rulings,
Stated decisions, the tasks, After execution), `replay.sh`.

Gotchas, besides the earlier handovers':

- **Edit scripts go through the Write tool**, never a heredoc in Git Bash: in this session a
  heredoc again turned `'\n'` inside Python into a real newline.
- **Write edit anchors against rustfmt's output**, not against what you wrote: `cargo fmt`
  reflows patterns and long lines, and the next script's anchor no longer matches.
- **The commit subject is `P6x-Tn: <title>`, nothing more**, as in P6a and P6b.
- **The plan's Before step must leave `git status --porcelain` empty**: an untracked file
  outside a task's paths is asked about before every commit (D80).
